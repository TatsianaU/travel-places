# Домашнее задание

## 1. Тема оформления

Разминка: соберите переключатель темы по образцу с сессии самостоятельно,
не подглядывая в готовый код. Цель — руками пройти весь
цикл Context ещё раз, пока он свежий.

Заведите глобальное состояние темы и переключатель между светлой (Light) и
тёмной (Dark) темами. При переключении цвета всего приложения меняются, а
выбор пользователя сохраняется между перезагрузками.

Требования:

- отдельный Context с `useState` (одно поле + одно действие, reducer здесь
  избыточен);
- три файла: `ThemeContext.ts` / `ThemeProvider.tsx` / `useTheme.ts` (хук с
  `throw` вне провайдера);
- две темы через CSS-переменные: значения для светлой в `:root`,
  переопределение в блоке `[data-theme='dark']`;
- минимум 3–4 переменных (фон страницы, поверхность, текст, приглушённый
  текст, рамка);
- `ThemeProvider` ставит `data-theme` на `<html>` и пишет выбор в
  `localStorage` — оба в `useEffect`;
- начальную тему читайте из `localStorage` через lazy initialization с
  валидацией (только `'light' | 'dark'`);
- кнопка-переключатель (Sun/Moon из `lucide-react`) без props, читает
  `{ theme, toggleTheme }` из хука;
- переведите хотя бы пару компонентов на `var(--color-...)`, чтобы увидеть
  перекраску.

Подсказки:

- `createContext<ThemeContextValue | null>(null)` — не заглушка: так вызов
  вне провайдера упадёт с понятной ошибкой, а не «молча не сработает»;
- lazy init — передавайте в `useState` саму функцию, без вызова:
  `useState(loadInitialTheme)`;
- перекраску делает браузер по CSS, React перерендеривает только
  потребителей темы — не меняйте цвета в JS;
- в `localStorage` может лежать невалидное значение — принимайте
  только значения `'light' | 'dark'`, иначе светлая тема по умолчанию.

### Третья тема (необязательно)

Добавьте третью тему оформления (например, «зеленая» или «высокий контраст»): свой блок
`[data-theme='...']` с переменными и переключение по кругу вместо тумблера
из двух значений. Не забудьте про валидацию нового значения при чтении из
`localStorage`.

## 2. Недавно просмотренные места

Добавьте историю недавно просмотренных мест.

При открытии `/places/:id` место добавляется в историю. На главной странице
покажите блок «Вы недавно смотрели» со ссылками на последние места.

Требования:

- отдельный Context с `useReducer`;
- храните только `id`, данные мест берите из TanStack Query;
- максимум 5 мест, новые добавляются в начало;
- повторный просмотр поднимает место наверх без дублей;
- кнопка «Очистить историю»;
- история сохраняется в `localStorage`;
- пустой блок не показывается.

Подсказки:

- reducer вынесите в отдельный файл;
- понадобится action для просмотра и очистки;
- данные из `localStorage` загружайте через lazy initialization;
- не вызывайте `dispatch` во время рендера страницы места — используйте
  подходящий эффект.

### Удалённые места (необязательно)

Если место удалено, не показывайте его в истории. Добавьте action для удаления
несуществующих `id`.

## 3. Toast-уведомления

Добавьте глобальные уведомления:

- «Место добавлено в избранное»;
- «Избранное очищено»;
- «Место удалено».

Требования:

- создайте `ToastProvider` и хук `useToasts`;
- список уведомлений храните через `useReducer`;
- уведомление можно показать из любого компонента;
- одновременно может быть несколько уведомлений;
- каждое закрывается само через 4–5 секунд;
- крестик закрывает уведомление сразу;
- подключите toast минимум к двум действиям.

Подсказки:

- у каждого toast должен быть уникальный `id`;
- `crypto.randomUUID`, `Date.now` и `setTimeout` нельзя вызывать внутри
  reducer — он должен оставаться чистым;
- не забудьте очищать таймеры;
- стили сделайте простыми, основная задача — Context и reducer.

### Пауза при наведении (необязательно)

При наведении остановите таймер, а после ухода продолжите отсчёт оставшегося
времени.
